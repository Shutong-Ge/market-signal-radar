# 投研舆情雷达 · AI 热点监控与晨报生成

面向基金投研团队的市场热点与舆情监控工具：**多源采集 → 三层去重 → 无K值聚类 → 四因子热度 → 混合检索RAG深度分析 → 投研晨报**，全链路自动化。

所有数据来自**公开免登录财经接口**，所有指标为**管道真实运行产出**（非演示数据）。

## 实测结果（首次完整运行，2026-09-05）

> 线上演示页每天早上自动重跑一遍，看到的是**当天**的数字；下表是留档的首次完整运行，用于说明各环节的量级与口径。

| 环节 | 结果 |
|---|---|
| 采集 | 3 家媒体 7 个公开频道，库内 1,747 条真实财经资讯 |
| 三层去重 | 窗口内 1,447 → 1,331 条（去重率 8.0%，耗时 35.3s，重跑幂等）<br>L1 标题哈希 42 · L2 自研SimHash 5 · L3 语义向量 69 |
| 无K值聚类 | 426 条相似边 → 1,168 个连通分量 → 过滤程式化公告 4 簇、单一媒体簇 49 个 → **43 个有效热点** |
| 热度分级 | 爆点 4 · 高热 8 · 升温中 13 · 一般 18 |
| 检索评测 | 两路召回集平均重合度仅 **40.1%**；只用BM25漏 1.88 篇/query、只用向量漏 2.12 篇/query |
| RAG 生成 | Top5 限流 + 7天缓存；模板降级 0/5；引用标注覆盖率 **0%**（本地1.5B局限，如实记录） |

## 核心设计

**① 去重必须分层** —— 财经资讯的重复有三种形态，一层解决不了：
- L1 精确：同稿多频道收录 → 标题归一化哈希，O(1)
- L2 近似：同一通稿改写标题/删节 → 自研 64 位 SimHash（jieba + 词频对数加权、汉明距 ≤3、64位切4段16位分块索引召回，鸽巢原理保证不漏）
- L3 语义：同事件不同表述 → bge 向量余弦 ≥0.90

指纹跨批次持久化（7天TTL），记录来源文章ID以保证重跑幂等。

**② 聚类不预设 K** —— 每天有几个热点本就不固定，K-means 的全局结构假设在此错误。改用向量近邻（余弦≥0.80）建边 + 并查集连通合并，簇数由数据决定；向量链路不可用时降级关键词规则聚类（8 大投研板块词表），**已实测验证**。

**③ 热度可解释且自适应** —— 四因子（覆盖度/爆发速度/持续时长/媒体覆盖）窗口内对数归一。社交因子（微博热搜）因需登录态且已风控而无数据源，触发权重动态归一分支；单日窗口内 duration 退化为常数时同样自动剔除——同一机制的两次应用。

**④ 混合检索用数据论证** —— BM25 + 向量双路 → RRF 融合（只用排名不用分数，规避量纲不可比）。配套对照评测脚本，用重合度/名次差/单路盲区三个口径量化"混合检索值不值"。

**⑤ 可溯源性靠架构不靠提示词** —— 引用清单由检索层独立产出、与报告并排展示。实测本地 1.5B 的引用标注覆盖率为 0%（提示词明确要求且给了带标注样例仍全部省略），架构层的溯源设计因此成为必需而非可选。

## 开发过程中修复的四个真实缺陷

1. **SimHash 剥离数字导致误去重**：通用文本处理默认剥数字，但财经资讯里数字就是内容——"南向资金净卖出30亿"与"50亿"、"日本20年期国债"与"40年期"指纹相同，8 条不同事实被误杀。修法：SimHash 专用分词保留数字并加倍计权。
2. **跨批次指纹破坏幂等**：重跑时全部命中自己写入的指纹（拦截数 8 → 1339）。修法：指纹记录来源ID，比对时排除当前输入集。
3. **固定归一化分母换环境失效**：原设计 /50、/20 使热度分全挤在 0.2–0.33、分级失效；改分位数硬截断又导致大量并列。最终采用窗口内对数归一。
4. **埋点缺口**：回补批次直连写库未计入采集日志，导致漏斗图上"去重后数量大于采集入库量"。未做数字对齐修饰，在工作台页面如实标注。

## 每日自动更新

演示页不是一次跑完就定格的快照。GitHub Actions 每天北京时间 07:30 跑一遍完整管道
（`.github/workflows/daily.yml`），把重建好的 `index.html` 提交回仓库，Pages 随即刷新。
页面顶栏写着这批数据真实的时间窗和生成时间——**不写"当日采集"这种会随时间变成假话的字眼**。

几个为了"能天天跑"而做的处理：

- **状态跨天延续**：`data/` 目录（SQLite + 向量）走 Actions 缓存带到第二天。指纹 7 天 TTL、
  RAG 结果缓存、重跑幂等都依赖它。缓存丢了也不会坏，当天从空库重新开始而已。
- **采集量体检**：采完先数一遍窗口内资讯，低于 200 条就让这次运行失败、不提交。
  源站不可达时宁可页面停在昨天，也不要发一个空看板上去。
- **生成引擎按配置降级**：runner 上不拉 3GB 本地模型。配了 `API_KEY` 就调线上模型，
  没配就走 `ENGINE=template` 模板降级，并在页面的治理指标里如实标出"本次无 LLM 产出"。
- **评测集随当天热点重建**：原来的 8 个 query 是手写死的，绑定 2026-09-05 那批语料；
  每天换语料后它们在库里找不到对应文档，重合度会退化成噪声。现改为从当天热度前 3 的事件
  各生成三种问法（原标题式 / 关键词式 / 去数字泛化），保证每个 query 都有真实对应文档。
  手写的那组保留为 `FALLBACK_QUERIES`，生成不出来时回落。
- **数据保留 14 天**：够 2 天分析窗口 + 7 天指纹 TTL 用，库长期稳定在几 MB。

要接线上模型，在仓库 Settings → Secrets 里加 `API_BASE` / `API_KEY` / `API_MODEL` 三个值即可，
不加也能正常出页面。

## 运行

```bash
pip install httpx jieba numpy faiss-cpu sentence-transformers rank_bm25 python-docx transformers torch

cd src
python collect.py            # 多源采集 → SQLite
python dedup.py 2            # 三层去重（窗口 2 天）
python cluster.py            # 无K值聚类 + 热度模型
python cluster.py --fallback # 验证降级链路（强制关闭向量）
python rag.py 5              # 混合检索 + Top5 深度报告
python eval_retrieval.py     # 检索对照评测
python brief.py              # 组装投研晨报（Markdown + Word）
python build_data.py         # 汇总本次运行 → output/ui_data.json
python build_ui.py           # 装配单文件工作台
python prune.py 14           # 清理 14 天前的数据（长期运行时用）
```

首次运行会下载 bge-small-zh-v1.5（约 100MB）与 Qwen2.5-1.5B-Instruct（约 3GB）。
接生产强模型：`ENGINE=api API_BASE=... API_KEY=... API_MODEL=... python rag.py`

```

```
